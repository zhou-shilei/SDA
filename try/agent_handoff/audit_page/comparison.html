请求字段从哪里来用途
document_idSDA 任务配置 / 文档清单标识当前 PDF，不是论文正文。
table_id、page表格裁剪和页面布局清单，再与 OCR 表格结果关联定位原表与页码，供证据追溯。
caption优先用已有表题；缺失时从坐标关联的 PDF 表题或同页表题 OCR 取标题行提供标题语义；不会附带附近正文段落。没有可用表题时保留为空，不虚构续表标题。
headers、rows表格 OCR / 结构化网格。每个单元格保留原文与 `table_id:R行C列` 地址完整表头、数据行和空单元格都在，模型能据原位置建立索引。
header_row_indices、cell_views显式结构优先；否则只在检测到明确表头词、端点/单位或已复核合并表头时使用启发式。无明确证据时表头列表为空，首行保留为数据说明表头行、跨行列结构及少量经复核的格子视图。
正文块 / 方法段落仍保存在 `document_blocks`、`assay_method_pages` 等源数据中不进入这次 Template 请求；后续 Reader 按需分 chunk 使用。

当前 49-Sructure 的 28 个 OCR 表格单元中，14 个有已核对的打印标题；剩余单元没有可用表题，caption 为空。实现会从已有 table.caption 优先取值，再从坐标关联的 PDF 表题或同页表题 OCR 解析；只发送 caption 字符串，不发送附近正文。常规请求的文档证据字段为 `document_id` 与 `tables`；超预算时附加 `omitted_table_ids`。重解析任务可能另带 `repair_findings` 控制修复范围。正文源数据仍保留给后续 Reader。此页上方的实验结果来自先前真实试跑；v7 提示词尚未另发模型请求。

05 / 如何选择下一步

根据实测缺口，决定正文要读多少。

值得下一步验证的方案

先读表格 → 列出缺少的语义字段 → 只补相关正文 → 再组装 Dataset

优先补明确的序列链归属、名称等同关系、实验方法段落；只在需要时读原页或原图。这样可以把“全量正文”改成“按缺口补正文”。这一方案尚未试跑，不能预先宣称与全量正文效果相同。

  • 两组共用同一套校验和导出器；带置信区间数值不被导出、donor 未传递等程序问题，会同时限制两组结果。
  • 初始 Dataset 中没有序列定义，完整序列配对为 0，并不等于所有序列映射都没被模型看懂；还要分别看原始回答和校验后保留量。
  • 这是单次对照，没有重复多次测量模型波动。参考结果也是模型产物，不能给出人工标准下的准确率。
