# SDA Studio

本分支为开发商体验版，默认进入“体验案例”；自带 4 个真实专利案例和 570 条记录。启动、依赖和体验步骤见 [RELEASE.md](../RELEASE.md)。

从 `dataagent/studio` 迁入原有 HTML、CSS 和 JavaScript，提供“数据集 / 数据录入 / 数据审阅 / 任务队列”、三栏审阅布局、关系图、中英文、列宽调整、PDF 缩放、人工修订和导出。原始文件哈希记录在 `migration_source.json`。

在 SDA 根目录启动：

```bash
bash studio/studio.sh start
```

打开 `http://127.0.0.1:4183/studio/`。远程 IDE 转发 **4183** 端口；code-server 也可使用 `/proxy/4183/studio/`。4180 和 4181 已有其他服务，因此这里默认使用 4183。

VS Code 运行任务 **SDA: 在 VS Code 内查看提取结果**，会先启动服务，再请求内置预览打开本轮专利报告。
也可执行 **Simple Browser: Show**，填入 `http://127.0.0.1:4183/studio/run.html`。
4183 端口已配置 `openPreview`，该端口链接默认交给 Simple Browser 打开。
顶部“运行概览”进入新的文档报告：总耗时、实际 token、实验关键词/标签、序列、
分子关系、覆盖缺口与原页证据。完整 PDF 新运行另外生成内嵌数据的 `report.html`，
可以使用已有 HTML Live Preview 打开，无需请求 JSON 后端。

首次加载并确认审核人身份后，会自动打开覆盖在真实界面上的新手引导：先新建靶点文件夹
（例如 TSLP），再到数据录入选择专利 PDF 并加入队列，解析完成后点击“审阅”，
选择 VH/VL 序列，对照原文后通过“修正”或“接受”逐项确认。共 6 个高亮步骤，支持上一步/下一步、
方向键、跳过及 Esc 关闭；关闭后返回原栏目，完成或跳过的状态保存在当前浏览器。
顶部“新手引导”可随时重看，支持中英文与窄屏。引导只切换栏目，不上传、领取、修订或推送记录。

姓名窗口下方可选择、拖入或粘贴 Codex `auth.json`（可选，最大 64 KB），点击“确认身份”时一起保存。
只检查登录文件结构；账号权限、额度和令牌刷新由实际解析时的 Codex 客户端验证。
本次浏览器标签页只保存与姓名绑定的随机引用，不保存文件内容；改名后需重新添加文件，
“移除”并确认后恢复服务器默认账号。取消窗口不会改变已保存的选择。
文件独立保存在 `.studio/codex-auth/`，目录权限 0700、初始登录文件权限 0600；不覆盖服务器账号。

`CODEX_HOME` 并清除继承的账号与服务地址覆盖。已提交任务保留原选择，清除标签页选择不会中断它们。
公开任务、队列和日志接口不返回凭据引用或登录文件。该入口沿用现有可信本地服务和姓名标识，
并非新增的多租户登录认证。需要重启 HTTP 服务；旧队列执行器空闲退出后重启，才会加载凭据隔离逻辑。

覆盖首次身份确认、全部步骤、键盘焦点、关闭后恢复、记忆状态、中英文、窄屏和只读请求。

## SDA 数据连接

- 自动发现 `results/*/dataset.json`；读取同目录 `template.completed.json`、单表 JSON、缺失清单和耗时报告。首次打开进入数据审阅，直接显示当前专利的真实记录。
- 使用 SDA 本地 PDF 按需渲染页面，依据本地 manifest 提供表格区域与裁图，不依赖 DataAgent 的源文件、后端或旧示例。
- 每条实验使用 `document_id + observation_id` 作为稳定标识，保留同一实体的多次实验。数值列适用于 IC50、EC50、KD 等指标，实验组显示指标名称。
- 仅使用已有来源和明确的 OCR 行匹配。HTML 结构不用于推测单元格矩形；缺少位置时保留表格级证据。缺失值与未执行的审核保留待复核状态。
- 数据集文件夹与发布快照、审核人记录保存在 `.studio/dataset.sqlite`。初始 SDA 文件夹为空；在审阅页勾选记录并点击“推送所选记录”后，数据集页才会出现发布快照。
- 数据集页支持多选删除文件夹或其中的已发布记录；“全选当前列表”仅选择筛选后可见的项目，删除前确认数量。删除文件夹会移除其中的全部发布快照，源 PDF、解析结果和审阅记录保留；删除后的记录可重新推送，空文件夹列表在重启后保持为空。
- 字段修订、标记和当前记录/字段/PDF 页码自动保存到服务端任务草稿；浏览器保留 `sda.studio.*` 本地副本，源提取文件不被覆盖。修订按文档和记录区分，避免不同文件的同名记录互相影响。
- 数据录入列表提供“处理用时”和“Token 用量”；悬停、键盘聚焦或点击数值可查看明细，Esc 或点击外部关闭。
  时间优先使用完整运行报告，续跑累计、复用 OCR 的重新提取和仅有局部耗时的历史记录分别注明范围。
  并行正文/表格 OCR 显示独立耗时，阶段明细不能直接相加。运行中显示已用时间，缺失统计显示“未记录”或“记录中”。
  Token 全部使用十进制 K（1K=1,000），明细包含各模型阶段、输入、输出和缓存输入；缓存输入不重复计入总量。
  有未知请求用量时显示已知部分及 ≥ 标识；本地 OCR 解码 Token 尚未计入。完成任务的累计用量不会被后续缓存检查的零请求快照覆盖。

## PDF 导入

可一次选择或拖入多个 PDF，按选择顺序逐个上传。每份文件使用同一次选择的解析引擎和当前提交人姓名。成功提交立即持久化并进入原有 FIFO 处理队列；重复文件跳过，上传失败的文件保留在表单中方便重试。

“任务队列”顶部也可直接点击“提交 PDF”选择文件，再点击“开始解析”入队。支持多选和拖入，并可选择解析引擎；与“数据录入”共用导入表单，切换栏目及队列自动刷新均保留已选文件。
队列页按两类任务组织：上方“PDF 解析任务”把上传表单、引擎选择和共享解析排序放在同一个区域；下方“人工标注任务”负责领取、继续标注和复核。解析队列刷新不会重建上传表单或清空已选文件。

## 多人标注与恢复

顶部“数据审阅”右侧的“任务队列”展示提交顺序、文件名、提交人、处理状态、当前标注人和已审阅记录数。可以搜索、筛选“我的任务 / 待领取 / 待复核 / 处理失败 / 已完成”，也可按提交人、状态、当前标注人组合筛选。人员选项来自完整任务列表，支持筛选未记录提交人和未领取任务；状态包含解析及人工标注各阶段。筛选与搜索取交集，每 5 秒自动刷新时保留选择，不影响上方共享解析队列。已审阅记录数统计至少有一个字段修正或审核决定的记录，不表示每个字段已全部核验。

1. 每位成员填写自己的姓名，点击“领取下一个”按提交时间领取最早的已处理文件，也可以领取指定文件。每人同时持有一个任务，服务端 SQLite 事务防止重复领取。
2. 在审阅页修订、接受或标记字段。工具栏展示保存状态；保存失败会提示重试，未保存时阻止提交任务并在离开页面时提示。
3. 刷新、退出或换浏览器后，填写相同姓名，在“我的任务”点击“继续任务”，恢复草稿与查看位置。姓名沿用现有操作者标识，不是新增的登录认证。恢复操作会使旧页面的写入凭据失效，避免旧页面覆盖新进度。
4. 暂时无法完成时点击“退回队列”，归还任务并保留草稿，下一位成员可接着处理。不会因关页或暂时离线自动清空归属。
5. “提交复核”进入待复核，由另一位成员领取；复核人可以“复核通过”“退回修改”或退回待复核队列。标注完成与推送数据集仍是两个独立动作。

任务和草稿保存在 `.studio/dataset.sqlite` 的 `review_tasks`，操作历史保存在 `review_task_events`；备份仍需包含整个 `.studio/`。删除文件前必须先归还其标注任务，相关草稿和历史随原有删除清单一起归档。

接口：`GET /api/reviews/queue` 返回共享列表；加 `?document_id=...` 读取草稿，读取响应不包含领取凭据。`POST /api/reviews/queue` 支持 `next / claim / resume / save / release / submit / approve / return`，写入要求领取凭据与当前版本。后台 PDF/OCR 队列继续使用独立的 `/api/queue`，文件处理完成后才可领取人工标注。

离线验证：`PYTHONPATH=src:tests python -m unittest test_studio_review_queue -v`。可选浏览器验证：`PYTHONPATH=src:tests python -m unittest test_studio_review_queue_browser -v`，需要 Playwright 和可运行的 Chromium；测试使用临时数据，不启动 OCR/LLM。

## 解析引擎

网页端统一使用 dataagent2；上传、重新解析和复用 OCR 重新解析均使用 dataagent2，不再提供引擎选择或“新建对比”入口。
两版共用相同的 PDF 预处理、正文 OCR，以及 VL 结构＋medium 裁行识别并拼接回填的表格 OCR。
dataagent2 完成本次表格分类和模板后，运行自己的分块 Reader、原文锚点序列物化与有限问答；
不运行 dataagent1 的序列提取或修复；最终 VH/VL 通过独立 `src/eval` 运行 ANARCI、ESM-2 和 OP。模型和推理强度沿用共享模板阶段的配置。
开发侧仍可通过 API 或命令行创建独立策略对比，保留原任务并复用已完成的 OCR。
API 为 `POST /api/patents/compare`，JSON 字段为 `document_id` 和 `extraction_engine`。
命令行也可用 `python studio/run_comparison.py --source <列表ID> --engine dataagent2`
提交策略对比；任务进入与网页相同的持久化队列，日志和产物位于对应 `.studio/patents/<对比ID>/`。
API 的上传表单和 retry/analyze JSON 可传 `extraction_engine=dataagent1|dataagent2`；
省略时新上传默认 dataagent2，重解析沿用原任务。非法值在创建任务之前拒绝。
dataagent2 产物保存在当前结果目录的 `shared_seed/` 和 `dataagent2/`，同时导出原有审阅格式；
运行统计包含本次共享分类/模板与新 Reader/问答的实际请求，不叠加历史基线。
Reader 或问答调用失败会保留部分结果并标记任务失败，真实缺项继续显示待复核。
`dataagent2` 的 `--resume` 暂不接入完整 PDF 入口；可在网页复用 OCR 并生成新运行。
更新后需重启服务加载后端；从旧版升级时须先等待旧执行器的任务结束。旧后端尚未加载 dataagent2 时会提示重启。

数据录入页支持点击或拖入 PDF，再点击“提交 PDF 并加入队列”。后台按提交顺序执行
`src/document/run_document_pdf.py`：先调用 `pdf2doc.py` 完成六步预处理，自动方向校正和裁图后，
全文与表格 OCR 在两个独立进程中同时执行；组装并导出结构化文档后，严格复用本轮证据运行
dataagent 表格分类、全文证据检索、实验绑定、序列提取及有限修复，再导出原有 SDA 模板和数据集。页面显示真实的版面、
OCR/抽取、模板、TST 和构建阶段，失败原因直接展示，运行日志可打开和刷新。
Studio 的 GPU VL 表格 OCR 默认按空闲显存自动选择并发，受完整表格实测的并发上限约束，
同时为并行全文 OCR 留出显存。CPU、非 VL 后端或无法查询显存时默认 1 路。
`--table-workers N` 或 `SDA_STUDIO_TABLE_WORKERS=N` 可显式覆盖；独立 pdf2doc CLI 的默认值保持 1。
选择结果、空闲显存与估算预算保存在任务 `ocr_configuration` 和日志
`table-ocr-configuration` 中，实际参数通过 `--table-ocr-workers` 传给完整 PDF 入口。
每批 VL 识别及序列裁行复核结束后释放闲置 CUDA 分配器缓存；模型权重继续复用，
不改变图片分辨率、推理精度、解码或 OCR 结果。完整测试记录见
`try/agent_handoff/benchmarks/49-Sructure-table-workers-20261102.json`。
每次运行使用新的产物目录；网页不会自动重跑已有专利。
统一结果位于运行目录 `document/structured/`；录入列表和运行报告可打开结构化 JSON，
报告也提供 Markdown。接口为 `/api/patents/<id>/structured.json`、`structured.md`、`structured.txt`。
网页显示两路 OCR 的独立状态；单路结束不会提前进入文档组装。

已有结果可选择“重新解析 PDF”完整重跑，或“复用 OCR 重新解析”跳过版面与表格
OCR，只读取保存的原始 HTML/文字及证据，重新调用抽取和补全。OCR 缓存缺失、
跨专利或不匹配时会报错，不自动回退到重新识别。两种操作都保留之前的运行目录，
内置样例不会覆盖 `data/`、`results/` 原始产物，也保持删除保护。
复用 OCR 重新解析时使用所选引擎，同时复用已保存的全文和表格 OCR；缺少全文 OCR 时提示先完整解析 PDF。
抽取在输入准备阶段失败、尚未导出逐表结果时，也可从保存的 OCR 检查点或结构化目录恢复，不必重新运行 OCR。
此模式在报告中明确标为“重新提取”，不当作整篇 PDF 首次解析耗时。

标题、实验方法和序列正文从 `structured/page_ocr/pages.jsonl` 检索，保留原文、页码及来源。
重新提取保留原裁图及 OCR，新的模型尝试和 SDA 导出写入新运行目录；不补读 PDF 文字层，不运行在线专利检索。

```bash
SDA_STUDIO_PYTHON=/path/to/sda/bin/python \
SDA_STUDIO_OCR_DEVICE=gpu:0 \
bash studio/studio.sh start
```

可设置 `SDA_STUDIO_PORT`、`SDA_STUDIO_OCR_BACKEND=vl|paddle`；CPU 可设 `SDA_STUDIO_OCR_DEVICE=cpu`。模型权重与 Codex 配置沿用 SDA 现有环境。上传解析会执行真实 OCR 和模型请求，错误写入 `.studio/patents/<id>/runs/<run>/pipeline.log`，也可通过 `/api/patents/<id>/log` 查看。
dataagent2 的失败提示显示具体阶段及原因；结果目录的 `failure.json` 保留原始校验错误和记录路径，
任务状态的 `failure_details` 保留对应诊断。整篇解析和复用 OCR 重新提取都保留这些原因。
Action 每次完整返回可做一次局部修复，第二次完整重试后仍可修复明确定位的错误，合并后重复完整
校验。需要复用成功 Reader 的开发侧恢复命令见 [dataagent2 说明](../src/dataagent2/README.md)；
该命令生成独立结果，网页现有“复用 OCR 重新解析”仍会重做提取。
全文后端由 `SDA_STUDIO_TEXT_OCR_BACKEND=paddle|vl` 配置，默认 paddle；表格后端默认 vl。
`SDA_STUDIO_TEXT_WORKERS` / `SDA_STUDIO_TABLE_WORKERS` 默认均为 1，避免同设备重复加载过多模型。
`SDA_STUDIO_OCR_EXECUTION=parallel|serial` 默认 parallel；显存受限时可选 serial，真实加速取决于设备与文档。

上传的源文件和产物放在 `.studio/patents/`，删除上传专利时移入 `.studio/trash/`，现有 `data/` 和 `results/` 的示例受保护。缺少有效运行汇总不会被当作解析成功。

## 多人提交与 GPU 排队

- 网页上传、整篇重跑、复用 OCR 重新解析和策略对比共用一个 FIFO 队列。任务及执行配置存入 `.studio/dataset.sqlite` 的 `task_queue` 表；`jobs.json` 继续提供兼容的任务状态，跨进程写入由工作区文件锁串行保护。
- 当前整个工作区固定 **1 个完整解析任务并发**。文档内部正文/表格 OCR 的并发仍由原有显存预算和 `SDA_STUDIO_TABLE_WORKERS` 控制。队列只调度本平台提交的任务，手动执行其他 GPU 程序不在其控制范围内。
- 数据录入页展示执行上限、运行中和等待中数量、每份文档的排队位次与前方任务数。等待时间与实际处理时间分开；空闲浏览器也定期刷新，以显示其他成员刚提交的任务。
- “任务队列”和“数据录入”顶部均展示共享解析队列：所有成员看到相同的执行顺序、专利号/文件名、提交人、状态/进度和北京时间的入队时间，每 5 秒同步。解析任务按服务端持久化队列 ID 排序，正在运行的任务在前；重试重新入队并排到队尾，不因原文档创建时间较早而插队。完成或失败的任务退出解析队列，仍保留在下方任务列表。自动同步保留队列表格滚动位置；标注列表的搜索和“我的任务”筛选不会隐藏其他成员的解析任务。
- 启动 HTTP 服务会启动独立 `queue_worker.py`，文件锁确保同一工作区只有一个常驻队列执行器；数据库事务也阻止多个消费者同时领取任务。网页服务每 5 秒检查执行器，异常退出后重新拉起。
- 新版 `studio.sh stop/restart` 只停止/重启网页服务；已提交的等待任务和正在执行的解析继续保留或运行。从仍使用内存队列的旧服务升级时，脚本继续拒绝中断旧服务中的活动任务。
- 旧版仍有任务时，可运行 `python studio/upgrade_when_idle.py --root "$PWD"` 等待其队列全部结束后自动备份 SQLite/任务状态并重启；进度写入 `.studio/queue-upgrade.json`。该程序不启动新解析，也不会中断旧任务。
- 等待任务在重启后继续排队。解析失败会释放位置，让下一份 PDF 执行；失败任务需手动重试。执行器意外退出时，若旧解析子进程仍活着，队列等待它结束，避免两份任务争抢 GPU；随后将中断运行标为失败，保留源文件、日志和已有产物，不自动重复付费请求。
- 队列状态接口：`GET /api/queue`；`GET /api/patents` 同时返回队列汇总和每条任务的排队位置。执行器日志：`.studio/queue-worker.log`，PID：`.studio/queue-worker.pid`。
- 维护整台机器时，先停止 HTTP 服务，再给队列执行器发送 SIGTERM；它会完成当前任务后退出，剩余等待任务保留。重启 HTTP 服务会恢复消费。备份须包含 SQLite、`jobs.json` 和 `.studio/patents/`。

离线队列验证：`PYTHONPATH=src:tests python -m unittest test_studio_task_queue -v`。
包含多进程争抢单 GPU 槽位、真实 HTTP 并发上传、独立执行器处理和网页服务中途重启；使用替代解析脚本，不调用 OCR 或 LLM。
