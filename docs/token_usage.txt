Token 用量统计

当前记录文档提取、覆盖修补以及序列规划/核验的实际模型用量。
codexllm 从 codex exec --json 的 turn.completed.usage 读取计数。
输出 _token_usage.json/.txt，按阶段、条目和专利汇总；计时与批次报告也引用这些统计。
文本报告使用 K/M 展示，JSON 保留精确整数。

计数：total_tokens = input_tokens + output_tokens。
cached_input_tokens 是输入的子集；reasoning_output_tokens 是输出的子集，不能再次相加。
uncached_input_tokens 为已知 input_tokens 减去已知 cached_input_tokens。
本地结果缓存命中不会发起新模型请求；服务端输入缓存仍记录在该请求中。
TemplateAgent 的确定性处理不调用模型，因此没有 API token 消耗。
本地 PaddleOCR-VL 使用本地 GPU，其推理 token 未纳入这份模型服务用量；已有耗时报告继续记录 OCR。

所有请求都记录，包括重试、失败、超时和取消。
CLI 没有返回用量时保留未知，并在 field_coverage 和 requests_without_usage 显示。
零次模型调用显示零；有调用但用量未知时不估算为零。
没有明确文档归属的请求保留为 _shared_or_unknown。
若使用自定义 LLM，需由它接入 record_current_usage；这些统计不会估算未接入的服务。
记录的是服务返回用量，不计算最终账单或估算未提供的价格。

历史 withouttmep 基线：
通过 archived _timings 请求窗口、原始应用提示词和表格内容，逐一匹配 89 个 Codex 子会话。
每个会话只取最后累计用量，核对原生 usage 记录；不把多次 token_count 累加。
包含校验失败响应及其重试，排除同期 IDE 代理会话和本地 OCR。
详细证据与会话文件哈希：baseline/withouttmep/_token_usage_recovery.json。
后补的用量报告属于派生统计；原归档中的运行结果及其原始校验值保持原样。
