正文序列Agent接入说明

运行位置
表格OCR/分类/提取结束 -> 按专利分块扫描正文 -> 按本篇SEQ ID关联序列
-> 合并序列库 -> costructure -> DataConstructionAgent。

默认行为
python src/graph.py --image-dir data --output-dir results

默认开启正文提取。每篇专利在 data/<专利号>/ 中读取以下一个来源，优先级从高到低：
1. patent_context.json（document_id + description/claims，或document_id + paragraphs）
2. patent_text.zh.txt
3. patent_text.txt
没有正文资料时沿用表格流程；只有正文没有图片的专利也能建立序列实体库。
正文来源应位于以专利号命名的目录；JSON中的document_id必须与专利一致。

参数
--text-context-dir：单独的正文资料根目录，默认与image-dir相同。
--text-sequence-max-chars：每块JSON字符预算，含段落元数据，默认12000。
--text-sequence-overlap-chars：块之间保留相邻段落的字符预算，默认600，不能超过块预算的1/4。
--text-sequence-concurrency：正文模型请求并发，默认0，表示同一专利全部文本块同时处理；例如20块则并发20个。正整数可显式限制并发数。
--no-text-sequences：关闭正文阶段。
--retries / --retry-delay：正文阶段复用批处理重试设置。

进度显示
图片进度到37/37只代表图片任务结束，后续还会执行正文扫描、序列拼接和最终数据构建。
正文阶段单独显示总块数、并发数、每块成功/缓存/失败及重试原因。
正文扫描和最终模型构建等待期间，每15秒打印一次状态；该间隔不会取消模型请求。

复用现有表格结果，只跑正文及拼接（不重新做OCR）
python src/text_sequences.py --data-dir data/WO2025108394A1 --result-dir results/WO2025108394A1 --output-dir validation_results/text_sequence_agent/WO2025108394A1 --construct-data

独立命令的参数还包括 --document-id、--max-chars、--overlap-chars、--concurrency、--retries。
不加--construct-data时，仍生成正文序列库和确定性costructure，但不调用最后的拼接Agent。
推荐先使用独立的输出目录查看结果。

提取与校验
- 按实施例及段落打包，长段落优先在句子边界拆分；同一条连续序列不从中间切开。
- 每块均交给TextSequenceExtractionAgent扫描，新分子不受现有实验名称列表限制。
- 每条记录保留name、region、sequence、seq_id、molecule_type、sequence_type、domain_role和evidence。
- 每个非空名称、区域、编号、实际序列都要求原文引文支持，未知段落或编造字符会导致该块重试。
- 同篇专利内按SEQ ID连接“名称/区域/编号”与其他块或表格中的实际序列。
- 原有表格记录保留；重复的正文序列合并来源，序列冲突保留候选，冲突的VH/VL不能进入最终结果。
- 核酸不翻译成蛋白；抗原、未知序列类型和双抗的分域信息保存在序列库，不填入平面的VH/VL。
- 只有序列没有实验的分子保存在entities中，最终六字段文件仍只为原始实验输出一行。
- 最终DataConstructionAgent收到完整可变区约束，明确同名VH/VL由程序回填，冲突区域强制null。

输出
results/<专利号>/text_sequences.json：正文提取及合并结果。
  records：有明确名称/区域/实际序列的合并序列记录，含证据。
  unresolved_records：缺名称或实际序列的已提取记录。
  entities：包含新分子的序列实体；可查看sequence_conflicts。
  conflicts：同一SEQ ID或同一分子区域的冲突。
  pending_tasks：缺失图片、超长不可分割序列等仍需处理的来源。
  chunks/errors/summary：文本块覆盖情况、失败原因及缓存统计。
  issues/issues_file：待核对问题及问题备注文件路径。
  synthetic_input：提供给两个拼接阶段的已校验补充序列输入，没有新增实验行。
review_issues.json / review_issues.txt：问题备注，含来源段落、错误原因、影响、处理建议和待核对状态。
_text_sequence_chunks/*.json：按正文指纹、提示词、文本块内容保存的校验后缓存。
costructure.json / data_construction.json：使用正文序列补充后的拼接结果。
_batch_summary.json 的text_sequences：正文阶段的成功、失败、跳过与各专利统计。

耗时记录
- 批处理根目录的_timings.txt：直接查看耗时排名、最长请求、峰值并发、排队和重试退避。
- 批处理根目录的_timings.json：包含全部请求/操作事件、阶段起止时间和排名。
- _batch_summary.json的timings/timing_file：同一批次的排名摘要及报告路径。
- 各专利text_sequences.json的timings：该文档正文阶段的耗时摘要。
- text_sequences.json的chunks[].timings：每块的实际耗时、排队、缓存命中和各次尝试。
- 各专利目录的_timings.json/_timings.txt：正文分块阶段明细。
- 独立text_sequences.py命令在指定输出目录生成报告；使用--construct-data时包含最终Agent拼接。
- 单图Graph返回的state.timings记录每个成功节点的实际耗时。

wall_seconds是本次实际耗时；phase_ranking按流水线阶段实际耗时排序。
stage_ranking的active_wall_seconds是请求/操作区间并集，避免并发请求重复计时。
request_seconds_sum是所有请求（含失败/重试）的累计耗时，并发时可大于实际耗时。
queue_wait_seconds_sum与retry_sleep_seconds_sum分别累计排队和重试退避时间。
OCR、分类、表格提取是重叠执行的，不能把它们的覆盖时间相加当成总耗时。
报告仅记录本次运行，缓存命中不会复用上次模型请求耗时；旧结果没有记录的耗时不能追补。

来源限制
当前新增Agent处理文字。网页图片占位会登记为missing_image_requires_pdf；
尚未实现PDF原图识别Agent或自动视觉核对。已知含错的PDF OCR层不会自动作为可靠序列灌入。
没有实际序列、序列类型不明、双抗归属不明或存在冲突时，保留待处理信息。
complete表示文字分块扫描完成；source_coverage=text_scanned_images_pending表示仍有图片资料待处理。
部分文本块在重试后仍未通过校验（ValueError），且有成功块时，正文标记partial，失败块记为warning待核对问题。
这类问题不会中断最终拼接，正常返回退出码0；_batch_summary.json.status为partial，text_sequences.partial计数，warnings包含备注。
未通过校验的块不会进入补充序列；已通过校验的结果保留，最终六字段记录不新增备注字段。
全部文本块失败、正文读取失败或请求运行故障仍记为error，批处理返回退出码1。
超预算片段也记为待核对问题；网页缺图限制仍在pending_tasks单独记录。
graph.py退出码1表示图片、正文或最终构建中存在处理失败，终端末尾会列出具体原因。
VS Code调试器可能在raise SystemExit(main())显示SystemExit: 1；该行负责返回退出码，根因见前面的错误提示和_batch_summary.json。

与此前人工试点的关系
context_annotations.json与patent_context.py是此前68条记录的人工核对流程。
新正文Agent不读取该标注文件，按当前输入自动提取、重新合并。
现有结果已变化时，旧人工标注的索引和哈希不能直接复用。

验证
python -m unittest discover -s tests -v
旧人工标注测试在输入哈希不匹配时会明确跳过；正文Agent测试使用独立输入覆盖长文分块、
新实体、跨块编号、原文引文、冲突、核酸/双抗隔离、失败重试、缓存与批处理接入。
