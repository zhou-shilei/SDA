方法的关键语义（论文第 3 节、Algorithm 1、附录 A/B）：
1. schema 是预先确定的领域定义，不让模型每次凭空发明输出列。对象、关系、字段携带类型、描述，以及是否唯一/是否动态的信息。
2. 按 schema 自上而下遍历。静态对象或字段默认单实例；动态对象或字段先识别相关上下文，再调用 Counter 判断实际出现数量。
3. 将实例总数和序号传给 Extractor，逐个抽取动态实例。没有证据时数量可以为 0，字段可以缺失；不能为满足模板而补造实例或数值。
4. 父对象下的相关子字段应在同一次实例抽取中保留关联，例如某一次实验的条件、数值、单位；不能独立跨实例拼接这些字段。论文示例为利息约定及其利率/起止时间。
5. Type Recognizer 按句子细分文档，利用类型表示规则或领域关键词识别证据；保留原句出现的次序。论文第 3.2 节还描述了 dense retrieval 的辅助通道。
6. 提示词包含领域定义、相关字段说明、上下文和具体问题。计数与内容抽取是不同任务；附录 B 展示计数整数输出和缺失值标记。

上游实现能复用什么、不能直接导入什么：
- README 明确将各 Agent 阶段整理成批量实验的输入输出脚本；没有 setup.py、pyproject.toml 或可直接实例化的通用 TSTAgent。
- On_CPL/prompt_construct.ipynb 中的 counter_construct_prompt / construct_prompt_based_on_counter 展示了计数后构造内容问题。其内容提示会带总数，依序输出多个实例；论文 Algorithm 1 更明确地逐个序号遍历。生产适配以论文定义的总数+序号为准。
- Hybrid_RAG/data_capture.py 的 type_recognizer(entity, key, texts) 实际只支持借贷判决领域，需要“法院裁定”“原告申诉”等分区，按主体、金额、日期、利率分流；不能直接用来处理抗体专利。
- 同文件 ParagraphSplit 支持中文标点分句。Hybrid_RAG/hybrid_rag.py 用 sentence nodes + 向量/BM25 检索，但返回顺序不等同于论文描述的原文顺序；SDA 适配应显式按句子序号重新排序。
- KGs/KG_class.py 的 KnowledgeGraph 和 KGs/dataset_KGs/* 是其知识图谱与 CPL 定义，依赖 networkx、matplotlib、plotly 等，并不是本项目需要的抗体领域 schema。
- 上游实验依赖 wayne_utils、llm_inferencer、llama_index、modelscope、作者机器本地模型路径等；未附完整 requirements，不能假定 clone 后可运行。
- 未发现上游许可证声明。保留仓库用于用户要求的研究与追溯；SDA 生产模块采用独立实现和方法引用，不复制其源码。
- 本次未执行上游 notebooks/scripts，没有加载不受信任的 pickle 数据，没有安装其推理/训练依赖。

SDA 的适配原则：
- 表格已经提供的测量值和来源作为种子记录。正文流程围绕 schema 的缺失字段提出问题，不能覆盖或移动已有测量值。
- VH/VL 为各自的结构对象；H/L chain、CDRH/L1–3、FRH/L1–4、SEQ ID 等作为其字段。只有原文明示或有明确定义的外部编号方法时才填 CDR/FR；不能按通用长度猜切分。
- IC50、KD 等实验为动态实例：使用 metric 类型 + 实验来源/条件区分。IC50-1/IC50-2 是实例序号，不是两个固定模板字段；unit 属于其各自的实验实例。
- 不同条件、方法、物种、靶点的同名指标不能合并。不同领域指标也不能互相改名。
- 计数要以可见证据为限，先去除重复引用。保留计数结果、每个抽取实例、引用句及来源定位，便于核验遗漏和重复。
- 当前若只实现规则/关键词证据识别，应表述为基于 TST 的领域适配；不要宣称已复现论文全部 dense 检索、few-shot 样例选择、模型或基准结果。
